# 数据采集时界面卡顿问题记录

- 日期：2026 年 11 月 3 日
- 涉及文件：`lsl_EEG/web/frontend.html`
- 问题状态：用户实测反馈正常

## 问题现象

通过 BLOOM 转发 LSL 脑电数据并开始采集后，项目界面出现明显卡顿。

## 排查结果

前端原来每收到一个 WebSocket 数据包，就立即调用 `updateChart()`，对显示的通道重新计算并绘制整个时间窗口内的波形。数据包连续到达时，这些重复计算和绘制会增加浏览器负担，是导致卡顿的一个明确性能问题。

## 解决方法

在 `frontend.html` 中增加 `scheduleChartUpdate()`，将连续数据包触发的绘图请求合并：

1. 数据包到达时，仍由 `processEEGData()` 按原方式接收并写入各通道缓冲区。
2. 数据处理完成后安排画面刷新。如果已有刷新在等待，就不再重复安排。
3. 延迟 40 毫秒后，通过浏览器的 `requestAnimationFrame()` 执行绘图，刷新频率最高约为每秒 25 次。

本次修改只调整前端波形的绘制频率，没有改变 LSL 数据接收、通道采样或后端处理。

## 验证结果

- 使用浏览器模拟连续发送 100 个数据包，确认绘图请求被合并，波形和统计信息能够更新。
- 用户实际采集测试后反馈没有问题。
- 当时的 Python 测试未运行：可用 Python 环境中未安装 `pytest`。

## 以后出现卡顿时

可以先检查采样率、显示通道数量和时间窗口，再分别观察浏览器和后端的资源占用。本次优化解决的是前端重复绘图这一处负担，其他设备或环境因素仍需要结合实际情况排查。
